Explicación general: instrucciones always-on y file-based

Las instrucciones personalizadas definen normas y guías que influyen automáticamente en cómo el agente genera código y resuelve tareas, sin tener que repetir el contexto en cada prompt. Si hay varios ficheros de instrucciones en el proyecto, VS Code los combina en el contexto del chat (sin un orden garantizado).

Always-on

Se incluyen automáticamente en cada petición de chat. Utilízalas para estándares de código, decisiones de arquitectura y convenciones que aplican a todo el proyecto.

File-based

Se aplican cuando el fichero sobre el que trabaja el agente coincide con un patrón, o cuando la descripción coincide con la tarea actual. Ideales para convenciones de un lenguaje o framework concreto.

Propósito de las instrucciones always-on

Estas opciones se aplican automáticamente a todas las peticiones de chat del workspace:

.github/copilot-instructions.md

Un único fichero Markdown en la raíz del workspace. VS Code lo detecta automáticamente. Ideal para estilo de código, stack tecnológico, patrones de arquitectura y requisitos de seguridad.

AGENTS.md

Uno o varios ficheros, en la raíz o en subcarpetas (experimental). Útiles si trabajas con varios agentes de IA y quieres un único conjunto de instrucciones reconocido por todos ellos.

Instrucciones de organización

Definidas a nivel de organización de GitHub para compartirlas entre varios workspaces y repositorios. Se activan con el ajuste github.copilot.chat.organizationInstructions.enabled.

CLAUDE.md

Compatibilidad con Claude Code y otras herramientas basadas en Claude. Se busca en la raíz del workspace, en .claude/ o en el home del usuario.

Ficheros .instructions.md: instrucciones file-based

Se aplican de forma condicional según el tipo de fichero o su ubicación, usando la propiedad applyTo con un patrón glob en la cabecera YAML del fichero. Por defecto se guardan en .github/instructions (workspace) o en ~/.copilot/instructions (perfil de usuario), y VS Code busca recursivamente en subcarpetas. 

---
name: 'Python Standards'
description: 'Convenciones para ficheros Python'
applyTo: '**/*.py'
---
# Estándares de código Python
- Sigue la guía de estilo PEP 8.
- Usa type hints en todas las firmas de función.
- Escribe docstrings para las funciones públicas.

Úsalas para convenciones distintas entre frontend y backend, guías específicas de un lenguaje en un monorepo, o reglas para ficheros de test y documentación.

Crear instrucciones a nivel de workspace en VS Code

Usa directivas específicas para un proyecto concreto. Ideal para arquitectura, convenciones del equipo y requisitos técnicos de ese repositorio.

  1. Abre la vista de Chat y selecciona Configure Chat (icono de engranaje) para abrir el editor de Agent Customizations, pestaña Instructions.
  2. Elige New Instructions (Workspace) en el desplegable, o ejecuta Chat: New Instructions File desde la paleta de comandos.
  3. Define la cabecera applyTo (o deja el fichero como copilot-instructions.md para que aplique siempre) y escribe las reglas en el cuerpo.
  4. Guarda, inclúyelo en control de versiones y pruébalo con una tarea real para validar que el agente sigue esas directivas.

Crear instrucciones de perfil de usuario en VS Code Copilot

Son reglas que se aplican en todos tus workspaces (guardadas en tu perfil de VS Code, por ejemplo ~/.copilot/instructions). Utilízalas para preferencias personales de comunicación, idioma y formato de respuesta.

  1. En la vista de Chat, abre el editor de Agent Customizations y selecciona New Instructions (User).
  2. Escribe directivas transversales que quieras mantener siempre, sin detalles de un solo repo.
  3. Activa Settings Sync (sección "Prompts and Instructions") si quieres sincronizarlas entre dispositivos.
  4. Revisa periódicamente estas reglas para mantenerlas útiles y actuales.

Prioridad y buenas prácticas

Cuando existen varios tipos de instrucciones, todas se envían al modelo, pero en caso de conflicto se prioriza en este orden:

  1. Instrucciones personales (nivel usuario) — prioridad más alta.
  2. Instrucciones del repositorio (.github/copilot-instructions.md o AGENTS.md).
  3. Instrucciones de organización — prioridad más baja.
  • Mantén cada instrucción corta y en una sola idea; divide la información en varias instrucciones si hace falta.
  • Incluye el porqué de una regla: ayuda al modelo a decidir mejor en casos límite.
  • Muestra ejemplos de código de patrones preferidos y a evitar.
  • Evita repetir normas que ya aplica un linter o formateador.
  • Guarda las instrucciones de proyecto en el workspace y en control de versiones para compartirlas con el equipo.
